# PVG–ANT Research Compass v1.0

**Canonical status:** governing reference  
**Scope:** the whole PVG–ANT Central Mind  
**Authority:** subordinate only to the honesty ceiling and proof certificates  
**Classification:** Governance / Research Program — not a mathematical theorem

## 1. ثابت المشروع

الهدف الأعلى الثابت هو:

> تطوير هندسة التقييمات الأولية إلى لغة بحثية تشغيلية تربط البنية الهندسية الضربية بأدوات نظرية الأعداد التحليلية، ثم استعمال هذا الربط لاكتشاف وإثبات مساهمات أصلية صحيحة — ولو صغيرة — في نظرية الأعداد التحليلية.

لا يتغير هذا الهدف بسبب كتاب جديد، تجربة سلبية، مسار Lean، أو انتقال بين جبهات فرعية.

## 2. فرضية المشروع الاستراتيجية

الفرضية التي يجب اختبارها، لا افتراض صحتها، هي:

> قد تعيد هندسة التقييمات تنظيم أجزاء مهمة من البنية الضربية، وتكشف تفكيكات أو مرصودات أو مبادئ نقل تجعل بعض مسائل ANT أوضح أو أبسط أو أقدر على الدراسة والبرهان.

نجاح الترجمة لا يثبت وحده هذه الفرضية. يجب تسجيل نوع المكسب:

```text
none | expository | structural | analytic | proof-producing
```

لا تُعامل `expository` أو `reinterpretation` بوصفها نتيجة أصلية.

## 3. البوصلة الحاكمة

\[
\boxed{
\text{Translation}
\rightarrow
\text{Original Question}
\rightarrow
\text{Lemma}
\rightarrow
\text{Proof/Test}
\rightarrow
\text{Certificate}
\rightarrow
\text{Reusable Knowledge}
}
\]

الكتب، المعرفة، Lean، Python، R، البحث الأدبي، والتجارب أدوات تُستدعى عند الحاجة داخل هذا المسار؛ ليست أهدافًا مستقلة.

## 4. الفلو القياسي للمشروع

كل جبهة بحثية تسلك الطريق نفسه:

```text
ANT problem
→ identify multiplicative core
→ encode in PVG
→ geometric decomposition
→ analytic transform
→ transfer lemma
→ estimate / proof / negative certificate
→ translate back to ANT
→ originality and PVG-necessity audit
→ integrate reusable knowledge
```

### 4.1 مسألة ANT

تُكتب المسألة أولًا بلغتها التقليدية وبمخرج محدد: هوية، لمّة، مبرهنة، تجربة تفنيدية، أو شهادة سلبية.

### 4.2 النواة الضربية

يُفصل الجزء الذي تحترمه التقييمات عن الجزء الجمعي أو الطيفي الذي يحتاج جسرًا إضافيًا.

### 4.3 ترميز PVG

يُحدد بدقة:

- نقطة التقييم `ν(n)`؛
- الدعم والارتفاع والمعايير؛
- صندوق القواسم؛
- الألياف الباقية؛
- المقاطع اللوغاريتمية؛
- المرصودات المستخدمة.

### 4.4 التفكيك الهندسي

لا يكفي الرسم أو إعادة التسمية. يجب أن ينتج الترميز طبقات، أليافًا، اتجاهات، طاقات، أو حدودًا قابلة للاستخدام.

### 4.5 التحويل التحليلي

يُربط المرصود الهندسي بأحد الكائنات التشغيلية:

- مجموع حسابي؛
- سلسلة Dirichlet؛
- حاصل Euler؛
- تحويل Mellin/Perron؛
- شخصيات أو تحليل Fourier؛
- غربال؛
- تكامل تباين أو قيمة كبيرة.

### 4.6 لمّة النقل

هذه بوابة البحث الحقيقية. يجب صياغة عبارة تنقل معلومة هندسية إلى تقدير تحليلي، أو العكس. بلا لمّة نقل يكون الناتج تفسيرًا أو تشبيهًا فقط.

### 4.7 الشهادة

كل مسار ينتهي بأحد الآتي:

1. برهان كامل؛
2. شهادة سلبية؛
3. عائق محدد و`missing certificate` مسمى؛
4. نتيجة تجريبية مصنفة دون ترقية.

### 4.8 العودة إلى ANT

تُصاغ النتيجة بلغة نظرية الأعداد التقليدية ليتمكن الباحث الخارجي من تقييمها دون قبول مصطلحات PVG مسبقًا.

### 4.9 اختبار الأصالة وضرورة PVG

يجب الإجابة عن السؤالين:

1. هل النتيجة أو الطريق معروفان في الأدبيات؟
2. إذا حُذفت لغة PVG، هل يبقى البرهان والفكرة تقريبًا كما هما؟

إذا كانت الإجابة الثانية نعم، فالتصنيف الأقصى غالبًا `Reinterpretation` أو `Proof economy`، لا آلية PVG أصلية قوية.

## 5. قاعدة المهمة أولًا

لا يبدأ تعدين معرفة أو كتاب أو أداة بلا مهمة محددة.

كل مهمة تبدأ بـ`Research Readiness Card` تحدد:

- السؤال والمخرج؛
- المعرفة السابقة اللازمة؛
- ما هو جاهز تشغيليًا؛
- ما يحتاج تفعيلًا؛
- ما هو ناقص؛
- الأدوات المطلوبة؛
- قرار `READY / NOT READY`؛
- معيار الإغلاق.

## 6. حالات المعرفة

كل متطلب معرفي يصنف إلى:

```text
available
indexed
extracted
integrated
operationally_ready
```

وجود المصدر محليًا لا يعني دمجه، ودمجه لا يعني جاهزيته للمهمة الحالية.

## 7. الاكتساب الموجه

إذا كانت المهمة `NOT READY`:

1. يُكتسب الحد الأدنى الكافي فقط؛
2. تُستخرج المبرهنة أو الأداة بشروطها وحدود خطئها ومصدرها؛
3. تُدمج في العقل بصيغة تشغيلية؛
4. يُعاد فحص الجاهزية؛
5. يتوقف التعدين فور كفاية المعرفة لمحاولة اللمّة.

لا تُقرأ كتب كاملة تلقائيًا إذا كانت الحاجة إلى مبرهنة أو فصل أو ورقة محددة.

## 8. استخدام الأدوات عند الطلب

### Lean

يستخدم عندما يخدم لمّة بحثية نشطة، يثبت بنية قابلة لإعادة الاستخدام، أو يمنع خطأ حدوديًا مهمًا. لا يفتح مسار Lean جديد لمجرد توسيع formalization المعروف.

### Python

للبناء الحسابي، التحقق، التجارب المسبقة، إعادة الإنتاج، وCI.

### R

لتنفيذ إحصائي مستقل أو اختبار متانة عندما يكون ذلك جزءًا من شهادة المهمة.

### البحث الأدبي

للأولوية، أحدث نطاق، الشروط الدقيقة، ومقارنة النتيجة المرشحة بالمعلوم. لا يقتصر على جمع المراجع.

### التجربة

للاكتشاف أو التفنيد أو فحص الصياغة، لا لتعويض البرهان.

## 9. نواة اللغة الدائمة

يبني المشروع `PVG–ANT Language Kernel` مرة واحدة ويعيد استعماله. تتضمن النواة:

1. معجم الكائنات؛
2. معجم العمليات؛
3. مكتبة الجسور الدقيقة؛
4. مكتبة التحويلات التحليلية؛
5. خريطة الفقد والحدود؛
6. اختبارات الفائدة غير الشكلية؛
7. أمثلة معيارية؛
8. قواعد الترجمة العكسية إلى ANT.

لا يعاد بناء جسر معتمد من الصفر في كل جبهة.

```text
L0 Vocabulary
```

لا يسمح نجاح مستوى ما بتكراره إلى ما لا نهاية. يرتفع سقف المرحلة التالية:

- بعد L1 يجب طلب تبسيط بنيوي؛
- بعد L2 يجب طلب لمّة نقل؛
- بعد L3 يجب طلب آلية أو لمّة أصلية؛
- بعد L5 يجب طلب مبرهنة أو تعميم.

## 11. بنية الأهداف

### ثابتة

- الرؤية الاستراتيجية؛
- النزاهة والتصنيف؛
- بناء اللغة الثنائية؛
- السعي إلى مساهمة ANT أصلية عبر PVG.

### عامة طويلة المدى

- نواة لغة متقنة؛
- مبادئ نقل قابلة لإعادة الاستخدام؛
- خريطة المجالات التي تبسطها PVG والتي لا تبسطها؛
- أول لمّة أصلية؛
- أول مبرهنة أصلية متواضعة؛
- ورقة قابلة للمراجعة العلمية.

### تشغيلية مرنة

تضاف أو تعدل بعد كل `Stage Review`، بشرط أن يحمل كل هدف:

- مخرجًا قابلًا للقياس؛
- معيار إغلاق؛
- علاقة مباشرة بالهدف الاستراتيجي؛
- سقف ادعاء؛
- متطلبات سابقة؛
- حالة مسجلة في `registries/program-goals.jsonl`.

## 12. قواعد منع التوهان

1. **جبهة بحث أصلية نشطة واحدة فقط.**
2. لا جبهة جديدة قبل إغلاق الحالية ببرهان أو شهادة أو عائق مسجل.
3. لا إعادة بناء لجسر معتمد.
4. لا تعدين معرفة دون طلب المهمة.
5. لا أداة دون وظيفة علمية مسماة.
6. لا مرحلة بلا مخرج قابل للتقييم.
7. لا ترقية لمجرد تحسن تجريبي.
8. لا اعتبار عدد الكتب أو الملفات مؤشرًا للتقدم البحثي.
9. لا خلط بين تقدم المعرفة، تقدم الترجمة، والتقدم البحثي.
10. لا Dataset أو model جديد عندما تكون الفجوة تحليلية أو برهانية.

## 13. مؤشرات التقدم

تُقاس المرحلة بـ:

- عدد الجسور المعتمدة القابلة لإعادة الاستخدام؛
- عدد لمّات النقل الصحيحة؛
- عدد الأسئلة التي صمدت أمام التدقيق الأدبي؛
- عدد اللمّات المثبتة أو المفندة؛
- مستوى النضج L0–L7؛
- وجود مبرهنة أصلية أو شهادة سلبية ذات قيمة؛
- مقدار اعتماد البرهان فعليًا على PVG.

لا تُقاس بعدد الكتب المقروءة أو الوحدات المغلقة وحدها.

## 14. معيار النجاح الاستراتيجي الأول

\[
\boxed{\text{One original, correct, modest ANT theorem in which PVG contributes materially}}
\]

قد يسبق ذلك نجاح أصغر: هوية أصلية، متباينة، لمّة نقل، نتيجة متوسطية، تصنيف، أو شهادة استحالة.

## 15. السقف العلمي

- لا RH/GRH progress بلا برهان كامل وشهادة؛
- الترجمة ليست مبرهنة؛
- التجربة ليست برهانًا؛
- formalization لا يمنح الأصالة؛
- إعادة الصياغة لا تمنح الأولوية؛
- Candidate Mechanism لا يرقى بلا تدقيق أدبي وشهادة مناسبة.

## 16. المراجعة المرحلية

بعد كل مرحلة يُنفذ `Stage Review` فقط، ولا يعاد تعريف المشروع. يجيب عن:

1. ماذا أصبح متقنًا وقابلًا لإعادة الاستخدام؟
2. ماذا ثبت أنه مجرد إعادة تفسير؟
3. ما الآلية أو اللمّة التي بقيت؟
4. ما المعرفة والأدوات المطلوبة للمرحلة التالية؟
5. ما السقف الأعلى الجديد؟

تُحدّث بعدها:

- حالة الأهداف التشغيلية؛
- مستوى النضج؛
- الجبهة النشطة؛
- بطاقة الفعل التالي.

ولا تتغير الرؤية العليا إلا بقرار استراتيجي صريح.
