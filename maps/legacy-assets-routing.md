# Legacy Research Assets Routing Map

**Purpose:** tell the Central Mind when to activate an external legacy asset without reopening it as an independent research front.

## Governing rule

```text
named task
→ readiness audit
→ identify missing capability or bridge
→ activate the smallest sufficient external asset
→ return the result to the Central Mind
→ deactivate the external asset
```

No external asset is continuously active.

## Routing table

| Task need | Activate | Expected output | Do not import |
|---|---|---|---|
| valuation-language example | `EXT-ASSET-PVG-WEB-001` | exact bridge or finite example | web application state |
| sieve information or wall diagnosis | `EXT-ASSET-PVG-SIEVE-001` | bridge, missing-certificate map, or lemma seed | whole historical project |

| certified zeta computation | `EXT-ASSET-ZETA-LAB-001` | numerical certificate and artifact contract | bulk datasets and GPU code |

| provenance or old maintenance history | `EXT-ASSET-DOCS-001` | source history or supersession note | old phase rules as live governance |

## Activation contract

Every activation record must state:

```text
Task ID
Asset ID
Exact missing capability
Smallest files/functions required
Input
Output
Certificate or validation method
Scientific ceiling
Knowledge returned to the mind
Deactivation condition
```

## Canonical ownership

- strategy, goals, active front, claims, and closure decisions belong to `PVG-ANT-Central-Mind`;
- heavy computation and presentation may remain external;
- formal mathematics belongs to the canonical `formal/lean/` tree;
- old repositories may provide evidence or source material, never live project truth;
- duplicate bridges are linked, not rebuilt.
